# Alerts and e-mail notifications

## Two levels of alerts

| Level | Generated by | Contains | Visible on |
| --- | --- | --- | --- |
| **Bank AML alerts** | each bank, every round, on the next 150 live transactions | Full case details (accounts, amount, format, score, patterns) | That bank's portal only (Alerts page) and e-mail to the bank's AML officer |
| **Consortium alert summary** | each bank, sent with its update | Counts (scored, high, medium) and pattern names only | Aggregator Alerts page, Control room feed |
| **System alerts** | aggregator | Quarantine, exfiltration attempt, forged update, ledger integrity failure, access refused | Aggregator Alerts page, Control room feed, Attack lab timeline |

High risk = score at or above the bank's operating threshold (best F1 on its validation data); medium = at or above half of it.

## When an e-mail is sent

| Event | Severity | Sender |
| --- | --- | --- |
| Bank quarantined | critical | aggregator |
| Raw-data exfiltration attempt blocked | critical | aggregator |
| Forged / altered update | critical | aggregator |
| Ledger integrity failure detected by Verify | critical | aggregator |
| A bank reports 3 or more high-risk transactions in a round | high (max 1 per bank per minute) | aggregator |
| High-risk transactions in this bank (internal case list) | high (max 1 per 30 s) | bank node |

## Configure real e-mail (Gmail example)

1. Turn on 2-step verification on the Google account, then create an **App password** (Google Account → Security → App passwords).
2. Copy `.env.example` to `.env` and fill in the values.
3. Load the variables before starting the node (PowerShell):

```powershell
$env:SENTINEL_SMTP_HOST="smtp.gmail.com"; $env:SENTINEL_SMTP_PORT="587"
$env:SENTINEL_SMTP_USER="you@gmail.com"; $env:SENTINEL_SMTP_PASSWORD="your-app-password"
$env:SENTINEL_ALERT_TO="officer@example.com"
python -m sentinel aggregator
```

With Docker Compose, the aggregator reads `.env` automatically. Use **Alerts & e-mail → Send test e-mail** to check.
Without SMTP settings, every e-mail is saved as an `.eml` file in `nodes/<node>/outbox/`, and the demo still shows it in the e-mail log.
Never commit `.env` (it is git-ignored).
